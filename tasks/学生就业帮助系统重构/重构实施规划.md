### 1.2 推断的现状技术栈（待核对）

| 层 | 推断 | 置信度 |
|---|---|---|

### 1.3 现状的 5 个结构性问题（重构要解决的）

1. **入口无强制校验**：`.html` 是物理文件，URL 直接访问即得页面，登录页只是「跳转惯例」，不是安全边界。
2. **口令存储不安全**：`admin/123456` 若明文入库，任一次库泄露即全量失守。
3. **无分层**：路由里混着 SQL、文件解析与业务判断，改一处牵全身。
4. **无授权校验**：管理端页面对普通用户「藏起来」而已，接口未鉴权。
5. **无迁移机制**：改表靠手写 SQL，无法演进。

## 2. 技术框架选型

选型原则：**与你现有工程链路保持一致**（同样一套 FastAPI + SQLAlchemy 2 + Alembic + Vue3 + ruff/pytest 约定），降低维护成本、复用既有启动/自检/CI 经验。

### 2.1 后端

| 关注点 | 选型 | 版本约束 | 理由 |
|---|---|---|---|
| Web 框架 | **FastAPI** | `>=0.115` | 原生依赖注入做统一鉴权；Pydantic v2 出入参校验；自带 OpenAPI 便于联调与答辩演示 |
| ASGI 服务器 | uvicorn[standard] | `>=0.30` | |
| ORM | **SQLAlchemy 2**（`Mapped[]` 声明式） | `>=2.0.30` | 类型友好；避免手写 SQL 拼接导致注入 |
| 迁移 | **Alembic** | `>=1.13` | 禁手改表；`alembic check` 可入 CI 做漂移检测 |
| 数据库 | **PostgreSQL 16**（Docker） | 16 | 与既有项目一致；JSONB 存题库/审核结果；后续如需 RAG 可平滑加 pgvector |
| 驱动 | psycopg[binary] | `>=3.1` | 本地 `DATABASE_URL` 用 `127.0.0.1`（双栈会让连接超时翻倍） |
| 配置 | pydantic-settings | `>=2.3` | `.env` → 配置对象；密钥只放 `.env` 且永不入库 |
| 认证 | **PyJWT(HS256)** + **pwdlib[argon2]** | `>=2.8` / `>=0.3` | 无状态 Token；argon2id 为当前推荐口令哈希 |
| 文件上传 | python-multipart | `>=0.0.9` | |
| 简历解析 | pypdf（PDF）/ python-docx（Word） | | 截图支持 PDF/Word |
| 后台任务 | **Celery + Redis**（长任务）/ FastAPI `BackgroundTasks`（轻任务） | `celery[redis]>=5.4` | 录音转写、题库生成是分钟级任务，不能阻塞请求 |
| 音频处理 | ffmpeg（系统依赖，容器内装） | | 格式统一为 16k 单声道后再送转写 |
| 校验/格式化 | ruff（check + format） | `>=0.4` | 与既有项目同一把尺 |
| 测试 | pytest + httpx | `>=8.0` / `>=0.27` | 覆盖鉴权、越权、改密失效三类关键用例 |
| 限流 | 自写失败计数（登录接口）+ 依赖级配额 | — | 避免引入额外中间件；登录失败按 `username+IP` 计数并短时锁定 |

### 2.2 前端

| 关注点 | 选型 | 理由 |
|---|---|---|
| 框架 | **Vue 3 + Vite 5** | 与你 AIResume 前端同栈；零额外学习成本 |
| 路由 | **vue-router 4** + `beforeEach` 全局守卫 | 入口强制登录的前端闸门 |
| 状态 | Pinia（仅 `auth` store）；其余组件本地状态 | 轻量，够用 |
| HTTP | 手写 `src/api/*.js` 封装 `fetch`（含统一 401 拦截） | 与既有 `api.js` 风格一致，不引 axios |
| 样式 | 原生 CSS + CSS 变量（延续霍格沃茨皮肤：深木色 + 米金 + 衬线标题） | 现状视觉零图表库，保持一致 |
| 构建校验 | `npm run build` 入 CI | 防止打包期错误漏到线上 |

### 2.3 明确不引入的东西

| 不引入 | 原因 |

## 3. 系统分层设计

### 3.1 分层与依赖方向

```
                         ┌──────────────────────────────┐
  浏览器 (Vue3 SPA)  ──▶ │  api/      路由层（薄）        │  只做：参数校验 / 鉴权依赖 / 调 service / 组装响应
                         ├──────────────────────────────┤
                         │  services/ 业务层（厚）        │  业务规则、事务边界、编排（解析→AI→落库）
                         ├──────────────────────────────┤
                         │  repositories/ 数据访问层      │  查询构造；禁止上层直接拼 SQL
                         ├──────────────────────────────┤
                         │  models/   ORM 实体            │  SQLAlchemy 2 声明式
                         └──────────────────────────────┘
       横切：core/config（配置）· core/security（哈希/JWT）· core/errors（统一异常）
             core/deps（get_db / get_current_user / require_admin）· core/logging
            schemas/（Pydantic 出入参，与 models 解耦）
            worker/（Celery 任务：转写、题库生成）
```

**硬规则**

1. 路由层不写 SQL、不写业务判断分支（除「不存在就 404」这类归属校验）。
2. 跨层只允许向下依赖；`services` 不许 import `api`。
3. 所有外部输入先过 Pydantic schema（`schemas/`），ORM 实体不出现在响应体里。
4. 事务边界在 service：一个业务用例一个事务（`with db.begin()`）。
5. 统一错误响应体：`{"code": "...", "message": "...", "details": null}`（沿用你既有约定），异常在 `core/errors.py` 统一转 HTTP 语义。
6. 每个新模型必须在 `models/__init__.py` 登记（漏登记会让 autogenerate 生成 `DROP TABLE`）。
7. 改模型后 `alembic check` 必须无差异，纳入 CI。

### 3.2 四大模块在前端的分层

- `views/`（页面级，负责取数 + 布局组合）
- `components/`（可复用块：`UploadCard` / `HistoryDrawer` / `ChatPanel` / `NavSideBar`）
- `api/`（一模块一文件，export 具名函数）
- 页面组件禁止直接 `fetch`，一律走 `api/`。

## 4. 认证与授权方案

### 4.1 用户模型

```sql
users(
  id            BIGSERIAL PK,
  username      VARCHAR(64)  UNIQUE NOT NULL,
  email         VARCHAR(255) UNIQUE,          -- 可空；仅用于后续找回
  password_hash VARCHAR(255) NOT NULL,        -- argon2id 编码串（含参数与盐）
  role          VARCHAR(16)  NOT NULL DEFAULT 'user',  -- 'admin' | 'user'
  status        VARCHAR(16)  NOT NULL DEFAULT 'active',-- 'active' | 'disabled'
  token_version INT          NOT NULL DEFAULT 0,       -- 改密后递增，旧 token 立即失效
  pwd_changed_at TIMESTAMPTZ,
  last_login_at  TIMESTAMPTZ,
  created_at / updated_at TIMESTAMPTZ NOT NULL
)
```

### 4.2 口令安全存储

| 项 | 方案 |
|---|---|
| 算法 | **argon2id**（`pwdlib[argon2]`），参数走库默认（内存/时间成本可调） |
| 盐 | 由算法内置生成，随哈希串一同存储；**不自造盐、不使用固定盐** |
| 存储 | 只存 `password_hash`；任何日志、异常、接口响应都不得回显 |
| 禁止 | 明文、MD5、SHA1、无盐 SHA256、可逆加密、`==` 直接比较口令 |
| 比较 | 统一走 `verify_password()`（常量时间比较） |
| 迁移 | 首次迁移中：读旧口径校验 admin/123456 → 成功后写入 argon2 哈希 → **删除旧字段/旧比对分支** |
| 强度 | 新注册与改密：长度 ≥8，且含字母与数字；前端给强度提示，后端**必须**再校验一次 |

### 4.3 Token 与会话

| 项 | 方案 |
|---|---|
| 形态 | JWT（HS256），**HttpOnly + SameSite=Lax Cookie**（生产 HTTPS 加 `Secure`） |
| Claims | `sub`(user_id) / `role` / `iat` / `exp` / `ver`(token_version) |
| 有效期 | 24h（可配 `jwt_expire_minutes`）；`jwt_secret_key` 只存在 `.env`，启动时若为默认值则**拒绝启动** |
| 刷新 | 本期不做 refresh token；到期重登（体量小，收益低） |
| 登出 | 清 Cookie；如需即时吊销，把 `jti` 写 Redis 黑名单（默认关闭，配置开关） |
| 改密 | `token_version += 1` → 所有旧 Token 在 `get_current_user` 中校验失败（等价「全端下线」） |
| 前端存储 | **不落 `localStorage`**（防 XSS 窃取）；Cookie 由浏览器自动携带 |

### 4.4 入口强制登录——双闸门 + 一条白名单

**闸门 1：后端全局依赖（权威）**

- 所有 `/api/**` 路由默认挂在「已认证」依赖下；未通过 → **401**（不带 `WWW-Authenticate` 细节泄露）。
- 白名单仅 3 个：`POST /api/auth/register`、`POST /api/auth/login`、`GET /health`。
- 实现方式：`APIRouter(dependencies=[Depends(get_current_user)])` 或统一 `router_registry` 挂载前缀依赖，避免「漏写一个 Depends 就漏一个洞」。

**闸门 2：前端路由守卫（体验）**

- `router.beforeEach`：无有效会话 → `redirect=/login?redirect=<原路径>`；`meta.requiresAdmin` 且非 admin → 跳 403 页。
- `api/` 封装统一拦截 `401` → 清本地状态 + 跳登录（避免「接口 401 但页面还停在工作台」）。
- 守卫只是体验层，**不作为安全边界**。

**物理隔离**

- 旧的多页 `.html` 一律**移出静态托管目录**（迁 `legacy/` 归档），不留可直接访问的页面入口；静态站点只暴露构建后的 SPA（`index.html` + `assets/*`，无业务数据）。

### 4.5 授权

| 角色 | 能力 |
|---|---|
| `user` | 四大模块的全部功能；仅能访问**自己的**简历/录音/题库/面试会话 |
| `admin` | 用户能力 + 使用日志 / 数据看板 / 语料库管理（**本次冻结，仅保证改造后仍可用**） |

- 管理端接口统一挂 `require_admin`；返回 **403**。
- 归属校验：登录态按 `user_id` 过滤；**跨用户访问一律 404**（不泄露资源是否存在）。
- 禁止「只判 `user_id IS NULL`」这类横向越权写法；归属过滤统一收敛到一个 helper。
- 管理端「用户列表/看板」等既有交互与字段**保持原状**，重构只替换底层实现。

### 4.6 admin/123456 的保留策略

| 要求 | 落地方式 |
|---|---|
| 用户名 admin、口令 123456 仍可登录 | 迁移脚本一次性把该口令以 argon2id 写入 `password_hash`；`role='admin'` |
| 管理权限原状 | 管理端路由、菜单、接口集合与权限判定口径**不改**；只把「鉴权入口」从旧散落逻辑收敛到 `require_admin` |
| 安全兜底 | 提供配置开关 `force_admin_pwd_change_on_first_login`（**默认关闭**，保持原行为）；文档中标注「上线前建议置 true」 |
| 口令弱的风险 | 登录接口对 admin 单独记录审计日志；连续失败按 `username+IP` 锁定（默认 5 次 / 15 分钟） |

### 4.7 其他安全点

| 风险 | 对策 |
|---|---|
| SQL 注入 | 全量 ORM / 参数化；禁字符串拼 SQL；搜索关键字走 `ilike` 参数绑定 |
| XSS | Vue 默认转义；禁用 `v-html`（确需富文本则白名单过滤） |
| CSRF | Cookie 鉴权 + `SameSite=Lax`；写操作校验 `Origin`；后续如需更严可加双提交 Token |
| 上传 | 校验扩展名 + MIME + 文件头；限制大小（录音 ≤500MB / 简历 ≤10MB）；存储目录在 web 根之外，下载走鉴权接口，文件名随机化（防路径穿越） |
| 越权 | 每个资源接口写「他人资源 → 404」用例 |
| 用户枚举 | 登录失败统一文案「用户名或密码错误」 |
| 注册滥用 | 注册接口限流；用户名黑名单（`admin`、`root` 等保留字） |
| 敏感信息泄露 | `.env` 不入库；日志脱敏（口令、Token、手机号、邮箱打码） |
| 依赖漏洞 | `requirements.lock`（pip freeze 快照）+ 定期审计 |

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 源码缺失导致反推偏差 | 迁移可能丢功能 | T-01 强制现状核对，未核对项一律不进入实现 |
| 旧库口令是明文/MD5 | 迁移期安全窗口 | `0003` 一次性重哈希；迁移前后对比行数；迁移脚本只读旧值不回显 |
| 前端全量重写工作量 | 工期拉长 | 按模块灰度迁移，保留 `legacy/` 作视觉基准；每模块完成即可独立验收 |
| 录音/题库生成是长任务 | 请求超时、用户体验差 | 上传即建任务（返回 job id）+ 轮询进度；Celery 独立队列 |
| 大文件上传被网关/超时拦截 | 功能不可用 | 分片上传预留设计；Nginx `client_max_body_size` 与超时参数对齐 |
| 管理端「冻结」被顺手改坏 | 违反要求 4 | T-13 专项校验；管理端代码改动需在 PR 中单独列出并说明 |

## 10. 待你确认的 3 项（影响 T-10 及之后）

1. **「返校列车」是什么？** 截图侧栏第 5 项，不属于你列的四大模块。默认按「保留为占位菜单项」处理；若为真实业务，需要补充功能说明。
2. **数据库是否允许用 PostgreSQL？** 本规划默认 PG 16（Docker）。若答辩/课程环境强制 MySQL 或 SQLite，需替换驱动与迁移细节（JSONB → JSON 等），请在 Phase 0 前确认。
3. **admin 是否要「首登强制改密」？** 默认**关闭**（保持要求 4 的原有行为）；开启可显著降低弱口令风险，但会改变 admin 的使用体验。
