学生就业帮助系统（霍格沃茨就业帮助）· 重构后工程化全景

依据《重构实施规划》（2026-09-27 待评审版）绘制 · 目标态：FastAPI 严格分层 + Vue3 SPA + JWT(HttpOnly) + PostgreSQL 16 · 管理端功能与权限口径冻结 · 黄色标注 = 待拍板 / 待选型

1

用户与前端

Vue 3 + Vite 5 · vue-router 4 全局守卫 · Pinia 仅 auth store · 页面禁止裸 fetch，一律走 api/ 封装

认证页 LoginView

登录 / 注册 / 改密三 Tab；口令强度 ≥8 且含字母数字，前端提示 + 后端再校验；「手机号登录」文案摘除（未实现）

主界面 HomeView

导航 5 项（简历评估 / 录音分析 / 面试题生成 / 模拟面试 / 返校列车）顺序与命名不变，按角色渲染；头像与历史入口保留

录音分析 AudioAnalysisView

三 Tab（录音转文本 / 角色审核 / 面试审核）+ 拖拽上传 + 「MP3/WAV/M4A，<500MB，≤60分钟」提示 + 历史记录

面试题生成 QuestionGenView

拖拽上传简历（PDF/Word，<10MB）· 生成进度条 · 题库详情按题目列表展示 · 历史可再次打开

模拟面试 MockInterviewView

双下拉（简历 + 题库，题库显示「127道题」）·「确认加载」后才能开聊 · 逐条流式问答 · 刷新恢复 · 清空与历史

管理端三页冻结

使用日志 / 数据看板 / 语料库管理 —— 交互与字段保持原状，只替换底层实现；普通用户访问 403

2

入口与鉴权（双闸门 + 一条白名单）

守卫只是体验层，后端全局依赖才是安全边界

闸门 1 · 后端全局依赖（权威）

所有 /api/** 默认挂在已认证依赖下；白名单仅 3 个：POST /api/auth/register、POST /api/auth/login、GET /health；未通过 → 401

闸门 2 · 前端路由守卫（体验）

router.beforeEach：无会话 → /login?redirect=；meta.requiresAdmin 非管理员 → 403 页；http.js 统一拦截 401 清状态跳登录

JWT + argon2id

HS256 · HttpOnly + SameSite=Lax Cookie（生产加 Secure）· 24h · claims 含 ver(token_version) —— 改密递增，旧 Token 全端失效；jwt_secret_key 为默认值时拒绝启动

授权与归属

require_admin 统一挂管理端接口（403）；归属过滤收敛到一个 helper，登录态按 user_id 过滤，跨用户一律 404（不泄露存在性）

admin/123456 保留策略

迁移 0003 一次性重哈希为 argon2id；登录失败按 username+IP 锁定（5 次 / 15 分钟）+ 审计日志；首登强制改密开关默认关闭

物理隔离

旧多页 .html 一律移出静态托管目录，归档 legacy/（只读基准）；静态站点只暴露 SPA 构建产物，无业务数据

3

业务主链路（四大模块 · 业务保真）

api/（薄）→ services/（厚）→ repositories/ → models/；事务边界在 service；外部输入先过 Pydantic

简历评估

上传三重校验（扩展名 + MIME + 文件头，≤10MB）→ pypdf / python-docx 解析 → AI 分析报告；文件名随机化防路径穿越

录音分析

一个上传入口 + 三种分析目的 —— 数据模型用 audio_jobs.purpose 区分（不建三张表）；ffmpeg 统一转 16k 单声道后送转写；异步长任务、进度可见、可重试

面试题生成

简历文件 → 解析 → 定制化题库（question_banks）；生成为分钟级长任务；历史记录可再次打开

模拟面试

会话由 (resume_id, bank_id) 二元组初始化；逐条消息落库（刷新可恢复）；「选完两者才能加载」交互不变；题库下拉显示题目数量

共用支撑：resumes（简历文件出入库）· usage_logs（每人每日调用限额）· audit_logs（管理端使用日志的数据源） 返校列车：侧栏第 5 项，非四大模块 —— 默认保留为占位菜单项（进「建设中」页），待拍板 §10-1
4

异步任务层（Celery + Redis）

录音转写、题库生成是分钟级任务，不能阻塞请求

worker/tasks/audio_transcribe.py

转写长任务 · 独立队列 · 进度可见 · 失败可重试（POST /api/audio/jobs/{id}/retry）

worker/tasks/gen_questions.py

简历 → 题库生成任务；生成结果 JSONB 入库

交互模式

上传即建任务（立即返回 job id）+ 前端轮询进度；轻任务走 FastAPI BackgroundTasks；ffmpeg 为容器内系统依赖

待选型（规划 P0 缺口）：转写引擎 —— 本地 whisper（CPU 转写 60 分钟音频约 1~2 小时）vs 云 API（密钥 / 计费 / 延迟）—— T-10 开工前必须定案，否则无法估时
5

数据层（PostgreSQL 16 · Docker 具名卷）

8 张业务表 · JSONB 存题库与审核结果 · 禁手改表

用户与业务表

users（argon2id 哈希 / role / status / token_version）· resumes · audio_jobs（purpose）· question_banks · interview_sessions(resume_id, bank_id) · interview_messages

支撑表

usage_logs（每人每日限额的记账源）· audit_logs（管理端使用日志 + admin 登录审计）

迁移（Alembic）

0001_init_users → 0002_init_business_tables → 0003_admin_password_rehash（一次性重哈希）；alembic check 无差异入 CI

文件存储

录音 ≤500MB / 简历 ≤10MB；存储目录在 web 根之外；文件名随机化；下载走鉴权接口（不暴露静态路径）

6

外部依赖与工程护栏

与既有 AIResume 工程链路同一套约定，复用启动 / 自检 / CI 经验

AI 通道

services/ai_client.py 统一封装：超时 / 重试 / 用量记账；OpenAI 兼容协议

质量门禁四关

ruff check+format 0 warning · alembic check 无差异 · pytest 全绿 · npm run build 成功 —— 外加 §5 业务保真对照表逐项打勾

CI 与提交钩子

GitHub Actions：ruff → alembic check → pytest → npm build；pre-commit（ruff check + format）

测试约定

专属标记造数 + 范围化清理（用户名 / 文件名前缀），禁止全表 DELETE；AI 配置用 monkeypatch 注入，不依赖本地 .env

待拍板三项（§10）：① 「返校列车」是否真实业务（默认占位）② 数据库能否用 PostgreSQL（若课程环境强制 MySQL/SQLite，JSONB → JSON、驱动与迁移细节需改）③ admin 是否首登强制改密（默认关）
+

本次重构要解决的 5 个结构性问题 → 对策

旧系统的病根与对应的新闸门（评审对照用）
1. 入口无强制校验（.html 物理文件 URL 直访即得）→ 后端全局鉴权依赖 + 前端守卫 + legacy/ 物理下线，三重封死；
2. 口令明文 / 弱哈希（admin/123456 直登）→ argon2id 一次性重哈希，旧比对逻辑全删，日志与响应永不回显；
3. 无分层（路由混 SQL / 文件解析 / 业务判断）→ api 薄 / services 厚 / repositories / models 四层，跨层只许向下依赖；
4. 无授权校验（管理端只是「藏起来」）→ require_admin 后端强制 + 归属过滤 helper + 跨用户 404 用例；
5. 无迁移机制（手写 SQL 改表）→ Alembic 版本化 + alembic check 漂移检测入 CI，模型必须登记 models/__init__.py。
