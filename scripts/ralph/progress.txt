## Codebase Patterns

- 工具层在 `backend/app/services/agent/tools.py`，`make_tools(db, user_id, anonymous_id, ctx)` 是**每请求闭包工厂**，工具实例绑定本次请求的 db 会话与归属者。
- **`kb_search` 必须始终是 `make_tools` 返回列表的第一个元素** —— `tests/test_agent.py` 与 `tests/test_agent_tools.py` 依赖顺序。
- 归属过滤统一走 `_owner_filter(model, user_id, anonymous_id)`：登录按 `model.user_id == user_id`，匿名按 `model.user_id.is_(None) & (model.anonymous_id == x)`；识别不到身份要**明确拒绝**而不是返回全部数据。
- 工具内部**必须吞掉异常**返回自然语言兜底 —— 工具无法返回 HTTP 状态码，抛异常会让整轮 Agent 崩。
- 工具返回值是给 LLM 读的**自然语言**，必须截断（单块内容 300 字上限的先例）。
- JSONB 列写入 Python `None` 会落成 JSON `null` **字面量**而非 SQL NULL，`is_not(None)` 过滤不掉，必须再判 `isinstance(value, dict)`。
- 限额/记账复用 `usage_service.count_today_usage_by_owner(db, action_type, user_id, anonymous_id)` 与 `usage_service.write_usage(...)`，不要新写 SQL。
- 测试要在 `backend/` 目录下跑（`.env` 相对当前目录读）；新测试用专属标记只清自己造的数据，不要 `DELETE FROM` 全表。
- ⚠️ 跑全量 pytest 会清空 `kb_chunks` / `kb_documents`（老 `tests/test_rag.py` fixture 行为），跑完需 `python -m scripts.seed_kb_preset` 恢复语料。
- 前端零图表库、零 UI 框架：可视化一律手写 SVG/CSS；组件内映射表用常量 + 回落原始值（参考 `HistoryView.vue` 的 `actionMap`）。
- **准入检查只有 `ruff check .`**：`ruff format --check` 对 `tools.py` 等既有文件本来就报警（HEAD 即如此），是前格式化时代留下的。**别顺手整文件格式化**（会造出大量与 story 无关的 diff），按邻近代码风格写即可。
- 工具在 `services/` 层**不得 import `app/api/`**（项目是 Router → Service → Model 单向依赖）。需要复用接口层查询时，先把它下沉成 service 函数，接口与工具都调那一份，不要复制 SQL。
- `created_at` 是 `server_default=func.now()`（事务开始时间），**同一事务插入的多行时间戳可能完全相同**——所有「取最近 N 条」查询必须带 `id desc` 兜底排序；测试里要控制先后就**显式传 `created_at=`**（`InterviewSession(created_at=...)` 会覆盖 server_default）。
- ⚠️ 开跑 pytest 前先确认 Docker Desktop 起来了：本项目容器是**已存在但 stopped**，用 `docker start ai-interview-db ai-interview-redis ai-interview-ollama`；`docker compose up -d` 会报 name conflict。DB 没起时 pytest 会**挂住不报错**（连接超时很长），别误判成死循环。
- 知识库可见性判据是 `kb_service._visible_clause`（`scope=public` 全站可见 / `private` 仅归属者），工具与接口都复用它；但测试里造的 `scope=public` 文档 `user_id` 与 `anonymous_id` **都是空**（与预置语料同形），按归属者清理清不掉 —— 测试数据要带**标题前缀**，清理时用 `title LIKE '前缀%'` 兜底（`tests/test_agent_tools.py` 的 `_KB_PREFIX`）。
- 开发库长期有 7 篇预置语料，凡「空库 / 精确条数」类断言都会被它干扰：要么只断言与总数无关的片段（如「仅显示前 20 篇」），要么 monkeypatch 掉查询函数隔离验证。
- **纯静态工具（如 `platform_help`）用同一套「别名元组 → 文案」路由**：对 topic 与别名都做小写化再判包含，**别名顺序即优先级**（具体主题排前，防泛词抢匹配），空 topic 或全不命中回落总览；这类工具不查库，`db` 传 `None` 也能跑通。
- 工具 `description` 要三段式（做什么 / 什么时候用 / 什么时候**不**用），易撞的工具互相点名排他（如 `kb_search` ↔ `platform_help`、`resume_lookup` ↔ `analysis_read`）。
- 描述的可校验写法：统一用**中文冒号小标题**「什么时候用：」「什么时候不用：」当锚点，测试断言 `len(description) > 50` 且两个锚点都在；再加一条「参数化清单 == `make_tools` 实际返回」的测试，新增工具漏写描述会直接红。
- 改描述属于**纯 docstring 改动**，不影响任何工具行为：断言描述不需要数据库，`make_tools(None, None, None, ToolContext())` 取 `.description` 即可（与 US-005 证明静态工具不查库同一手法）。
- ⚠️ ruff 实际启用的是**扩展规则集**（含 `RUF100` / `BLE001` / `B008` / `SIM`），但 **`E402` 未启用**：照 `scripts/eval_rag.py` 写 `sys.path.insert` 后再 import 时**不要加 `# noqa: E402`**（会被 RUF100 判为多余指令）；吞异常一律写 `except Exception:  # noqa: BLE001  原因`，与既有代码一致。
- 写可测脚本（CLI 评测类）的套路：把「一次 LLM 调用」抽成注入的 `ask: (question) -> BaseMessage`，`run(cases, ask)` 只做纯统计；测试里用**替身模型**（只需实现 `bind` / `bind_tools` / `invoke` 三个方法返回 `AIMessage(tool_calls=[...])`）即可离线覆盖。测 `main()` 时 monkeypatch 三件套：`load_cases` / `REPORT_PATH`(tmp_path) / `build_chat_llm`。
- 路由评测只需**工具 schema**，不要执行工具：`make_tools(None, None, None, ToolContext())` 拿描述 → `build_chat_llm().bind(temperature=0).bind_tools(tools)` → 读 `msg.tool_calls[0]["name"]`；模型直接文字作答时用 `NO_TOOL` 占位计入未命中。
