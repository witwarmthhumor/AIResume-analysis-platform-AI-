# 算法与数据结构常见考点

## 什么是时间复杂度和空间复杂度

时间复杂度衡量算法执行时间随输入规模的增长趋势，用大 O 表示法描述，忽略常数项和低阶项。常见复杂度从优到劣：O(1) 常数（哈希查找）、O(log n) 对数（二分查找）、O(n) 线性（遍历）、O(n log n)（快排、归并）、O(n²)（冒泡、双重循环）、O(2^n) 指数（暴力递归）。空间复杂度衡量算法运行时额外占用的内存（不含输入本身），同样用大 O 表示，如递归的调用栈深度 O(n)、原地排序 O(1)。分析要点：循环嵌套决定复杂度级别，递归要考虑栈深度，哈希表是"空间换时间"的典型。实际工程中 n 很大时复杂度差异是数量级的，所以算法选型要先看复杂度。

## 数组和链表的区别与适用场景

数组在内存中连续存储，链表通过指针相连（单链表、双向链表）。数组的优点：随机访问 O(1)（下标直接寻址），CPU 缓存友好（连续内存局部性好）；缺点：插入删除需要移动元素 O(n)，扩容要拷贝。链表的优点：插入删除 O(1)（已知节点位置时），不需要连续内存；缺点：随机访问 O(n) 必须遍历，每个节点额外存指针（内存开销），缓存不友好。适用：频繁按下标访问用数组（如哈希表底层、堆），频繁在中间插入删除用链表（如 LRU 缓存、消息队列）。Java 里 ArrayList 底层数组，LinkedList 底层双向链表。工程上数组用得更多，因为缓存局部性和随机访问优势明显。

## 什么是哈希表，如何处理哈希冲突

哈希表（散列表）通过哈希函数把 key 映射到数组下标，实现平均 O(1) 的查找。哈希冲突是不同 key 映射到同一下标。处理冲突的常见方法：1) 链地址法：每个桶存一个链表或红黑树（Java HashMap 的做法，冲突多时链表转红黑树），简单、删除方便；2) 开放定址法：冲突后按探测序列找下一个空位（线性探测、二次探测、双重哈希），适合负载因子低、数据量可控的场景（如 Redis 的 dict 用链地址，ThreadLocalMap 用线性探测）；3) 再哈希：用多个哈希函数，都冲突才换。负载因子（元素数/桶数）决定冲突概率，Java HashMap 默认 0.75，超过就扩容。哈希函数要分布均匀、计算快，字符串哈希常用 MurmurHash、FNV。

## 什么是二分查找，有什么前提

二分查找（Binary Search）在有序数组中每次把搜索范围减半，时间复杂度 O(log n)。前提：1) 数据必须有序；2) 支持随机访问（数组），链表不适合。实现要点：维护左右边界 [left, right]，取中间 mid = left + (right - left) / 2（防止溢出），比较目标值决定向左或向右收缩，注意边界条件的开闭区间写法。常见变体：找第一个等于目标的、找最后一个小于目标的、找插入位置（lower_bound）。工程应用：数据库索引定位、有序列表查询、求平方根、旋转数组查找最小值。虽然简单，但边界条件写错是高频 bug（死循环、越界），建议写完后用奇偶长度的数组各测一遍。面试中二分查找几乎是必考基础题。

## 排序算法怎么选

常见排序及复杂度：快排（平均 O(n log n)，最坏 O(n²)，原地不稳定，实际最快）、归并排序（稳定 O(n log n)，需要 O(n) 额外空间，适合链表和需要稳定的场景）、堆排序（O(n log n) 原地不稳定）、插入排序（O(n²)，数据基本有序时接近 O(n)，小数组开销低）、冒泡/选择（O(n²)，仅教学意义）。Java 的 Arrays.sort：基础类型用双轴快排，对象类型用归并（稳定）。工程选型：数据规模小（<50）用插入排序（常数小）；大规模不稳定快排（注意最坏情况，可随机化基准）；要求稳定用归并；内存受限用堆排序；基本有序数组用插入排序或 TimSort（Python/Java 内置）。面试要求：快排和归并能手写并能分析最坏情况；理解稳定性的含义（相等元素相对顺序不变）。

## 二叉树、二叉搜索树、平衡树

二叉树每个节点最多两个子节点。二叉搜索树（BST）满足左子树所有节点 < 根 < 右子树，中序遍历得到有序序列，查找插入删除平均 O(log n)，但退化成链（如插入有序数据）变 O(n)。平衡树解决退化问题：AVL 树严格平衡（左右子树高度差 ≤1），旋转保持平衡，查询最快但插入删除旋转频繁；红黑树近似平衡（最长路径不超过最短 2 倍），旋转次数少、插入删除性能好，Java TreeMap、C++ map、Linux 内核都用红黑树；B 树/B+ 树是多叉平衡树，减少磁盘 IO 次数，数据库和文件系统用它。工程中直接用现成实现（TreeMap、SortedSet），面试考察点：BST 的查找插入删除实现、如何判断一棵树是 BST、中序遍历应用、平衡树的平衡条件。

## 什么是递归，递归和迭代怎么选

递归是函数调用自身解决问题，核心是找到递推关系和终止条件（基线条件）。递归天然适合树/图遍历、分治（归并快排）、回溯（N 皇后）、动态规划自顶向下。优点：代码简洁、思路直接。缺点：每次调用压栈 O(n) 空间，过深会栈溢出；重复计算（可用记忆化）。迭代用循环+显式栈模拟递归，无调用栈开销，但代码复杂。选型：深度浅（<1000）且思路递归清晰用递归；深度不确定或很大用迭代（或尾递归优化——Python 不支持尾递归，深递归会 RecursionError）；能自底向上 DP 就不用递归。工程上注意：Python 默认递归深度 1000，可 sys.setrecursionlimit 调大但不要滥用；树的遍历、目录遍历这类天然层级结构递归最自然。

## 什么是动态规划

动态规划（DP）把复杂问题拆成重叠子问题，记录子问题答案避免重复计算。适用特征：1) 最优子结构（大问题最优解包含子问题最优解）；2) 重叠子问题（子问题被重复计算）。解题四步：定义 dp 状态（dp[i] 表示什么）→ 找状态转移方程（dp[i] 怎么由前面的推出来）→ 初始化（base case）→ 确定遍历顺序。实现方式：自顶向下记忆化递归、自底向上表格。经典题：斐波那契、爬楼梯、背包问题（0/1 背包、完全背包）、最长公共子序列 LCS、最长递增子序列 LIS、编辑距离。空间优化：很多二维 dp 可以滚动数组压成一维。对比贪心：贪心每步取局部最优且不回溯，DP 要考虑所有子结构——能用贪心的问题更简单，DP 是更通用的"暴力+记忆化"。

## 图的遍历与最短路径

图分有向/无向、有权/无权，存储用邻接矩阵（密集图、查边 O(1)）或邻接表（稀疏图，省内存）。遍历：BFS（广度优先，用队列，找无权最短路径、层序遍历）和 DFS（深度优先，用栈/递归，判断连通性、拓扑排序、环检测、回溯）。最短路径：无权图用 BFS；单源正权用 Dijkstra（贪心 + 优先队列，O(E log V)，不能处理负权）；负权用 Bellman-Ford（可检测负环）；全源用 Floyd（O(V³)，适合小图）。拓扑排序：有向无环图的线性顺序，Kahn 算法（不断删入度为 0 的节点）或 DFS 后序，用于任务调度、依赖解析。工程场景：社交网络（BFS 求几度人脉）、地图导航（Dijkstra/A*）、构建工具依赖顺序（拓扑排序）。

## 字符串匹配与常用字符串算法

字符串匹配：朴素逐个比对 O(n*m)；KMP 算法利用 next 数组（最长公共前后缀）失配时跳过已匹配部分，O(n+m)，核心是构造 next 数组和失配回退；BM、Sunday 从右往左匹配通常更快。其他经典题：反转字符串、回文判断/最长回文子串（中心扩展 O(n²) 或 Manacher O(n)）、字符串哈希（滚动哈希 Rabin-Karp，用于模式匹配和判重）、Trie 前缀树（字典树，单词前缀查询 O(L)，用于自动补全、词频统计）、后缀数组/AC 自动机（高级）。Python/Java 的字符串不可变，频繁拼接用 StringBuilder/join。面试考 KMP 较少但要知道原理，Trie 和字符串哈希更实用，最长回文子串是高频手写题。

## LRU 缓存如何实现

LRU（Least Recently Used，最近最少使用）缓存：容量满时淘汰最久没被访问的 key。要求：get/put 都 O(1)。实现：哈希表 + 双向链表：哈希表存 key→链表节点，双向链表按访问时间排序，头是最新访问，尾是最久未用。get：命中则把节点移到头部；put：存在则更新值并移到头部，不存在则插入头部，超容量则删除尾节点并删哈希表对应项。为什么用双向链表：删除任意节点需要 O(1)，单向链表删除要找到前驱需要遍历。为什么哈希表：定位节点 O(1)。这就是"空间换时间"和数据结构组合的经典。Java 的 LinkedHashMap 覆写 removeEldestEntry 即实现 LRU；Redis 的近似 LRU 用采样代替精确链表以省内存；工程上还有 LFU（按频率淘汰）变体。
