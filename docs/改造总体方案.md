# AIResume 企业级改造 · 总体方案

> **版本**：v1（目标已校准为 AIResume 原地改造）
> **日期**：2026-09-29
> **定位**：**在既有 AIResume 上改造**，不是新建项目，也不改视觉皮肤。
> **参照物**：用户提供的 6 张截图，**仅作「企业级标准」参照**（界面不照抄，不套霍格沃茨皮肤）。

---

## 0. 一句话结论

在 AIResume 原地做四件事：**① 入口强制登录 + 用户名注册/登录/改密 + 内置 admin/123456 ② 会话保持（登录态 + 跨时段找回历史）③ 导航收敛到「简历评估 / 模拟面试」两个业务模块 ④ 企业级安全与稳定性收口**。客服 / 在线对话 / 知识库 / Playground 从导航收起但**代码保留**。

## 3. 认证改造（本次核心，风险最集中）

### 3.1 用户名注册 / 登录（决策：#2 统一改成用户名）

| 步骤 | 做法 |
|---|---|
| 加列 | `users.username`：`String(64)` / **unique** / NOT NULL，带迁移 |
| 数据迁移 | 既有账号由 `email` 前缀派生用户名（`a@b.com` → `a`）；**重名追加 `_2`、`_3`**；迁移脚本打印对照表 |
| 登录接口 | `POST /api/auth/login` 入参由 `email` 改为 `username`；**过渡期同时接受邮箱**（判断含 `@` 即按 email 查）→ 老用户零感知 |
| 注册接口 | `POST /api/auth/register` 入参加 `username`（3~64，仅字母数字下划线）；**保留字**屏蔽（`admin` 等） |
| 唯一约束冲突 | 返回 409 + 明确文案（用户名已存在 / 邮箱已被占用） |

### 3.2 修改密码（新增）

- `POST /api/auth/change-password`：校验原密码 → 新密码强度（≥8 位含字母数字）→ `token_version + 1` → 清 Cookie 要求重登
- **`users.token_version` 新列**（迁移）：JWT 里带 `ver` 声明，校验时比对——**改密后所有旧令牌立即失效**（等价全端下线）
- 前端：`ProfileView` 增加改密表单（原密码 / 新密码 / 确认）

### 3.3 内置 admin / 123456

- 新增 `backend/scripts/seed_admin.py`：**幂等**（已存在则只修 `role='admin'`，**不覆盖已改口令**）；口令 argon2id 入库
- ⚠️ **必须同时处理「首个注册用户自动提权 admin」**：该逻辑与内置 admin 冲突，且在新库上等于「谁先注册谁是管理员」= 安全洞。
  **方案**：加开关 `auto_promote_first_user`（默认 **关**），并把内置 admin 作为唯一管理员来源

### 3.4 入口强制登录（决策：#3）

**目标**：匿名用户不可再用任何业务功能。

**手段（低改动面，推荐）**：在**入口层**拦截，不动 25 个文件：

1. 后端：`/api/**` 全局闸门（现有 `auth_deps.get_current_user` 提升为中间件级默认拒绝，白名单仅 `register` / `login` / `health`）
2. 后端：**停止签发 `anonymous_id` Cookie**（`get_anonymous_id` 不再写入）
3. 前端：`navItems` 的 `requireAuth` 全部改 `true`；未登录一律跳登录面板并保留原路径

**匿名分支的代码保留**（在强制登录后成为**不可达路径**），不删。理由见 §9 R1。

### 3.5 其它认证项

| 项 | 改造 |
|---|---|
| Cookie 有效期 | `jwt_expire_minutes` 上调至 **7 天**（L1 会话保持）；`httponly` / `samesite=lax` 维持 |
| 登录失败锁定 | 进程内字典 → **Redis 集中计数**（多 worker 正确，沿用已有 `redis` 依赖） |
| 时序均等化 | 用户不存在也走一次假哈希校验（防用户名枚举） |
| 越权 | 跨用户一律 **404**（沿用现有 `owner_clause` 的 404 语义，不改成 403） |

## 4. 会话保持（两层，必须分别验收）

| 层 | 语义 | 实现 |
|---|---|---|
| **L1 登录态保持** | 关掉页面、隔一段时间再打开仍是登录态 | Cookie `max_age` 提到 **7 天**；前端启动问 `/api/auth/me`，登录态**唯一以后端为准**（已是现状，✅ 保持） |
| **L2 跨时段找回历史** | **不同时间登录，都能找回并继续历史对话** | ① 简历评估历史：`analyses` 列表按 `user_id` 过滤 + 详情回看<br>② 模拟面试历史：`interviews` 会话与消息已按用户落库 → 列表 + `GET /{id}` 恢复全部消息<br>③ **「继续上次会话」快捷入口**（新增 `users.last_active_session_id`）<br>④ 前端两个模块的「历史记录」抽屉补齐空/加载/错误三态 |

> ⚠️ L1 只解决"要不要重新输密码"，L2 才解决"上次聊到哪还能不能接上"。**只做 L1 = 登录着但对话没了**。

## 5. 数据模型变更

| 表 | 动作 | 说明 |
|---|---|---|
| `users` | **增列** | `username`（unique，NOT NULL）、`token_version`（int，default 0）、`last_active_session_id`（int，nullable） |
| `chat_sessions` | 复用 | 已有用户归属；强制登录后 `user_id` 恒非空 |
| `analyses` / `interviews` | 复用 | 已有用户归属，L2 直接用 |
| 迁移 | **1~2 个** | ① `username` + 数据回填（含重名处理）② `token_version` + `last_active_session_id` |

**约定**：改模型必须走 Alembic；NOT NULL 新列必须带 `server_default`（否则有数据的库上 `ADD COLUMN NOT NULL` 直接失败）；改完 `alembic check` 必须无差异。

## 6. 接口变更

| 方法 | 路径 | 变更 |
|---|---|---|
| POST | `/api/auth/register` | **入参加 `username`**（保留 `email` 可选） |
| POST | `/api/auth/login` | **入参 `email` → `username`**（过渡期兼容邮箱） |
| **POST** | **`/api/auth/change-password`** | **新增** |
| GET | `/api/auth/me` | 响应加 `username`（`UserOut` 投影同步） |
| PUT | `/api/me/profile`（若有） | 头像/资料保存（个人中心）；如不存在则新增 |
| GET | `/api/analyses` · `/api/analyses/{id}` | 语义不变，强制登录后 `user_id` 恒非空 |
| GET | `/api/interviews` · `/api/interviews/{id}` | 同上；新增 **`GET /api/interviews/last`**（继续上次会话） |
| — | `/api/agent*` `/api/chat*` `/api/kb*` `/api/playground` | **代码保留、接口保留**，仅从导航收起（不再对外露出） |

## 7. 实施步骤（每步可独立验收 + 可回滚）

> 顺序原则：**先做"不会破测试"的底座，再动认证入参**（认证入参一变，大量测试用例会连带失败，必须单独一步集中处理）。

### A0 · 基线与护栏（0.5 人日）
- 记下当前基线：`pytest` 通过数、`ruff check`、`alembic check`、`npm run build`
- 建分支 `feature/auth-rework`；确认三容器 healthy；`scripts/check_env --skip-ai`
- **验收**：基线数字写入方案附页（后续每步与之对比，**不允许"这次少跑几个用例也算过"**）

### A1 · `users` 加列 + 数据回填（1 人日）
- 迁移：`username`（unique NOT NULL + `server_default`）、`token_version`、`last_active_session_id`
- 回填脚本：email 前缀 → username，重名 `_2/_3`，**打印对照表**
- `UserOut` 加 `username`；`seed_admin.py` 幂等播种 admin/123456
- 关闭「首用户自动提权」（开关默认关）
- **验收**：迁移可升可降；`alembic check` 无差异；4 个既有账号（含 2 个演示号）都能拿到 `username`；admin 可用 `admin/123456` 登录

### A2 · 认证入参切换 + 改密（1.5 人日）
- `register` / `login` 改用户名；**邮箱兼容分支**保留
- 新增 `change-password` + `ver` 声明校验
- 登录锁定迁 Redis；时序均等化
- **集中修测试**：所有用 `email` 登录的用例改为 `username`（这一步预计触及大量测试文件，**单独一个提交**便于回退）
- **验收**：注册→登录→改密→旧 Cookie 401→新口令登录全链路；锁定 5 次生效；`pytest` 恢复基线

### A3 · 入口强制登录（1 人日）
- 后端 `/api/**` 默认拒绝闸门 + 停止签发 `anonymous_id`
- 前端 `requireAuth` 全 `true` + 未登录跳登录面板并保留原路径
- **验收**：未登录访问任意 `/api/**` 一律 401（含不存在的路径）；匿名 Cookie 不再出现；`pytest` 恢复到基线（**匿名用例改为"必须已登录"或删除，逐个说明**）

### A4 · 导航收敛 + 会话保持 UX（1.5 人日）
- 用户端导航 = 首页 / 简历评估 / 模拟面试 / 个人中心；首页卡片收敛为两项
- 两个模块补「历史记录」抽屉（列表 / 打开 / 空态 / 加载 / 错误重试）
- 「继续上次会话」入口（读 `last_active_session_id`）
- 个人中心加改密表单
- **验收**：真机走通「登录 → 简历评估 → 出报告 → 登出 → 隔一段时间 → 重新登录 → 从历史打开刚才那份报告」；模拟面试同理；`npm run build` 通过

### A5 · 安全与交付收口（1.5 人日）
- 越权用例覆盖全部资源类型；日志脱敏复核；上传校验复核
- 四关全绿；`check_env` 自检；README/AGENTS 口径同步
- **验收**：`ruff check` / `alembic check` / `pytest` / `npm run build` 四关全绿；演示数据脚本可用；打 tag

## 11. 支线 S1：模拟面试 LangGraph 化（必做，排在 A5 之后）

### 11.1 为什么做（对照《Agent 项目六大硬核标准》）

| 标准 | AIResume 现状 | S1 的贡献 |
|---|---|---|
| 3 规划/恢复/验证 | v2 图已有 planner/verifier/PostgresSaver 断点续跑；**面试场景未上图**——`stage`/`turn_count` 已阶段化，但崩在半程只能**重放消息**，不能从 checkpoint 续跑 | 面试流程建成图后：**进程崩溃 → 重启从 checkpoint 续跑，不重放不重复计费**——标准 3「失败恢复」的具体化叙事 |
| 5 可观测测评 | trace 落库 + 三套评测基线（RAG/路由/e2e） | 面试每一步（出题/评分/追问）进 trace；**先建面试评测集再改图** |
| 6 人机协同 | v2 interrupt 审批现成 | 面试结束报告生成前可加"确认出报告"审批点（可选） |

### 11.2 范围与做法
