用户与交互

简历分析台

上传 PDF → 解析正文 → 六块 AI 报告（岗位匹配 / 优势 / 短板 / 关键词缺口 / 建议 / 预测面试题）

模拟面试

四阶段状态机 · SSE 逐字流式 · 消息落库刷新可恢复 · 结束生成分维度评价报告

只读管理面板

统计卡片 + 用户列表 + 近 7 日用量；首个注册用户自动成为 admin

2

接入与鉴权

请求触达业务逻辑之前必须过的四道关

Nginx / Vite 代理

静态托管 · SPA history fallback · /api 反代；proxy_buffering off 保证 SSE 不被缓冲

JWT + Argon2

HttpOnly Cookie 无状态鉴权，前端 JS 读不到；登录失败按 IP + 邮箱计数，10 次锁定 15 分钟

归属隔离

登录按 user_id、匿名按 anonymous_id；跨用户访问一律 404，不泄露存在性

双轨限流

基于 usage_logs 按日聚合；当时只覆盖三类动作：parse / analysis / interview_message

3

业务主链路

Router → Service → Model 三层，业务逻辑不下沉到路由

简历上传与解析

扩展名 + magic bytes 双校验 · 5MB / 5 页 · SHA-256 去重不重复计费 · pypdf 提取 · 软删除可审计

AI 简历分析

固定 JSON 结构 + Pydantic 校验 + 失败重试 2 次；PROMPT_VERSION 入库可追溯，命中缓存直接返回

模拟面试

intro → technical → deep_dive → wrapup；消息逐条落库；最大轮次防无限聊；智能出题按 position_type 调难度

历史记录

按「简历 / 分析 / 面试」分组汇总本人数据；此时还没有使用日志明细与筛选（v3.3 才有）

4

AI 封装层

此时只有「一次调用一份结构化输出」这一种形态，尚无检索与工具编排

统一 AIService

OpenAI 兼容协议单一出口；换模型 = 改 .env 三行（BASE_URL / MODEL / API_KEY）

结构化输出治理

固定 JSON 结构 → Pydantic 强校验 → 失败自动重试（最多 2 次）；失败留痕写库不白屏

流式通道

仅面试使用：SSE 逐字推送面试官回复，前端打字动画；无工具事件、无引用来源

成本可见

每次调用写 usage_logs（prompt / completion token 与耗时）；max_tokens 设上限控成本

演进去向：v3.0 在本层之上叠加 RAG 知识库检索（pgvector + Ollama embedding）；v3.4 引入 LangChain ReAct Agent；v3.5 扩到 11 个工具并做混合检索 当时的能力边界：模型只能凭「简历正文 + 提示词」作答，无法查平台语料、无法读取历史面试记录、无法感知用户用量
5

数据与基础设施

Docker Compose 只编排两个容器：db 与 redis

PostgreSQL 16

6 张业务表：users / resumes / analyses / interview_sessions / interview_messages / usage_logs；原生 PG 镜像，无 pgvector

Redis 7 + Celery

简历解析 / AI 分析异步化，任务状态可查；appendonly 持久化 · 具名卷

本地文件存储

简历原文件落在 uploads/（Web 根目录之外，不提供目录遍历）；尚无独立数据卷

大模型通道

OpenAI 兼容协议（当时 DeepSeek / 通义互换验证）；Key 只放 backend/.env，永不入库

前端构建

Vue 3 + Vite；零 UI 框架、零图表库 —— 手写 CSS 设计系统与 fetch 封装

演进去向：v3.0 换 pgvector/pgvector:pg16 镜像、新增 kb_documents / kb_chunks 两表与 HNSW 索引、加 Ollama 容器；v3.1 再加 chat_sessions / chat_messages —— 最终 10 张表、8 次迁移
