## 四、AI 客服后端（LangChain Agent + 全程流式 + 历史）

### 4.1 依赖与配置
- requirements：`langchain>=0.3`、`langchain-openai>=0.2`（不引 community/langgraph）。
- config：`daily_agent_limit:int=30`、`agent_max_iterations:int=6`。

### 4.2 新增服务文件
| 文件 | 职责 |
|---|---|
| `services/agent/__init__.py` | 包导出 |
| `services/agent/llm_factory.py` | `get_agent_llm()`：ChatOpenAI 复用 settings，**streaming=True**（才能逐 token 回调），temperature=0.3 |
| `services/agent/tools.py` | `make_tools(db,user_id,anonymous_id)` 闭包工厂，构造 `kb_search`（内部调现有 embed_texts+search_chunks，不改） |
| `services/agent/executor.py` | 组装 AgentExecutor + **流式事件生成器**（见 4.4） |

### 4.3 新增 `api/agent.py`（自洽，不改 chat.py）
| 方法/路径 | 作用 |
|---|---|
| GET `/api/agent/sessions` | 当前归属的 **agent 类型**会话列表（session_type='agent'，按 updated_at 倒序） |
| POST `/api/agent/sessions` | 新建 agent 会话（受 chat_create 同级别每日上限约束，记账） |
| DELETE `/api/agent/sessions/{id}` | 软删除（严格校验归属，404 不泄露存在性） |
| GET `/api/agent/sessions/{id}/messages` | 历史消息（**含 tool_steps / citations**，正序） |
| POST `/api/agent/ask` | **SSE 问答**（见 4.5） |

### 4.4 全程流式实现（同步栈：后台线程 + 队列 + 回调）
项目是同步 FastAPI + 同步 SQLAlchemy，不引入 async DB。用 LangChain `BaseCallbackHandler` 捕获过程，后台线程跑 Agent，主生成器从 `queue.Queue` 取事件 yield 给 SSE：

```python

    def on_tool_start(self, serialized, input_str, **kw):   # → action 事件
        q.put(("action", {"tool": serialized["name"], "input": input_str}))
    def on_tool_end(self, output, **kw):                  # → observation 事件
```

- token 统计：回调 `on_llm_end` 累加 usage 或 `get_openai_callback`，done 返回总计。

### 4.5 `/api/agent/ask` SSE 流程
1. 限流 `enforce_daily_limit('agent', daily_agent_limit)`；
2. 有 `session_id` → 校验归属；无 → 自动建 agent 会话；
3. 存用户消息（chat_messages，role=user）；拉该会话历史转 `HumanMessage/AIMessage` 作 `chat_history`（只取纯文本，工具步骤不进上下文）；
4. `stream_agent(...)` 逐事件转 SSE：`meta / action / observation / delta / done / error`；
5. 流结束后存 AI 消息：`content=最终答案`、`tool_steps=步骤JSON`、`citations=检索来源`、`tokens`；更新 session.updated_at、用首问生成 title（同在线对话策略）；
6. finally 记账 action_type=`agent`；异常推 error 事件并正常断流。

SSE 事件：
```
meta{session_id}  action{tool,input}  observation{tool,preview}
delta{content}    done{content,iterations,tokens_total,citations[],message_id}
error{content}
```

## 十一、风险与兜底
1. **流式区分决策轮/最终轮**：tool_calls 决策轮无文本 token，最终轮才出文本；真机校验，必要时用"最近一次 on_tool_end 之后的文本流"作为最终答案，确保不把决策碎片打进回答。
2. **后台线程 + 同步 DB**：工具在 worker 线程内用请求级 Session，注意 Session 不跨线程复用——工具闭包捕获的 db 在同一 worker 线程内同步使用即可（请求生成器期间 Session 存活）；若出现跨线程问题，改为在 worker 内自建 Session 并在结束时关闭。
3. **SSE 与线程异常**：worker 异常经队列回传 error 事件，保证前端不卡死、连接正常关闭、失败也记账。
4. **历史上下文长度**：chat_history 只取最近 N 轮（建议 10 轮）纯文本，避免超上下文窗口。
5. **迁移兼容**：新列均有默认值/可空，旧行无需回填；downgrade 可干净回退。
6. **双端会话隔离**：所有 agent 会话查询带 session_type='agent' + 归属过滤，杜绝与在线对话串列、跨用户泄露。
