③ AI 客服主链路 · v1（LangChain create_agent，ReAct 工具循环）
同步栈 + 异步图桥项目是同步 SQLAlchemy / 同步路由；daemon 线程内 asyncio.run 跑 astream_events，事件推入线程安全 queue.Queue，主生成器取队列转 SSE
循环上限recursion_limit = 最大工具轮数 ×2 + 余量，语义对齐旧版 max_iterations
▼ SSE 事件协议：meta →（reset → action → observation）* → delta* → done；异常走 error
action / observationon_tool_start / on_tool_end：工具名、入参预览、结果预览；工具异常只回中性话术（不泄露 SQL/路径）
resetDeepSeek 工具决策轮会同时吐文本 token，属中间过程——清空累计回答，通知前端同步清空
delta / finalon_chat_model_stream 逐字下发；最终回答 = 累计 delta，空则退最后一条纯文本 AI 消息

③′ 一键求职准备流水线 · v2（LangGraph StateGraph + PostgresSaver）默认开
planner规则式：固定单链路计划 + 入口意图识别；无 JD 且无主题 → fail
load_resume定位本人最新简历；无可用简历 → fail（不调模型不耗额度）
need_analysis查是否已有有效分析，条件边路由 analyzer / matcher
analyzer无有效分析才调 AI；落 analyses 表 + 记账
matcherJD 与本人简历做岗位匹配分析
questioner围绕主题/JD 生成一组模拟面试题
▼ verifier 产物校验：缺字段/空产物 → 回环对应产出节点（每节点 ≤2 次），超限 → fail
hitl_gate · interrupt风险动作「创建面试场次」建 pending 审批单后图挂起；审批单创建幂等，TTL 30min
deliver批准后才执行 create_session（零审批零副作用）；汇总分析/匹配/题目，发 done
断点续跑PostgresSaver 持久化每步；approve / reject 用 Command(resume) 从 hitl_gate 继续
retry-node / abort失败可新建 run 并注入已完成产物；审批中可放弃；approve/abort 一律条件更新乐观锁
启动时 lifespan 回收孤儿 run：planning/running → failed（服务重启），waiting_approval 刻意不动留审批；事件经 event_bus 发布，断线重连先发 DB 快照再订阅补发
