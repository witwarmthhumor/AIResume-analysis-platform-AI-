一、概述
================================================================================
本计划合并两个需求，统一施工：

需求A：把 Playground 更名为「在线对话」，并新增多会话管理（创建/删除
       对话，对话列表侧栏，效果参考 Right Code 平台）。
需求B：语料库管理从 Playground 迁移到管理端独立视图，用户端 Playground
       不再显示语料库面板。

两个需求都涉及 Playground.vue 的重写，合并施工可避免重复改动：
Playground.vue 直接重写为「在线对话」视图（含对话列表侧栏 + 聊天区，
不含语料库面板），语料库管理由新增的 KbAdminView.vue 承担。

2.3 数据持久化方案【决策点2，重要】
--------------------------------------------------------------------------------
方案A（推荐）：后端数据库持久化
  - 新增 chat_sessions + chat_messages 两张表
  - 登录用户按 user_id，匿名用户按 anonymous_id（项目已有此机制）
  - 刷新不丢、换设备登录可同步
  - 工作量：新迁移 + 5 个 API + 前端状态管理
  - 与项目 interview_sessions 持久化模式一致，作品集完整度高

方案B：前端 localStorage
  - 对话存在浏览器本地，刷新不丢，清缓存/换设备丢失
  - 无需后端改动，工作量小
  - 登录/匿名不区分，都存在本地

方案C：纯前端内存（当前模式）
  - 刷新丢失，最简单但体验差，不推荐

【推荐方案A】，理由：项目已有面试会话持久化，在线对话保持一致更专业；
匿名用户用 anonymous_id 机制已成熟。

2.4 后端设计（方案A）
--------------------------------------------------------------------------------
新增模型 backend/app/models/chat.py：

  ChatSession（对话会话）
  - id            bigint PK
  - user_id       bigint 可空 索引（登录用户归属）
  - anonymous_id  varchar(64) 可空 索引（匿名用户归属）
  - title         varchar(100) 默认「新对话」
  - created_at    timestamptz 索引
  - updated_at    timestamptz 索引（列表排序依据）
  - deleted_at    timestamptz 可空（软删除）

  ChatMessage（对话消息）
  - id            bigint PK
  - session_id    bigint 索引（逻辑关联，与项目惯例一致，不建物理外键）
  - role          varchar(20)（user / assistant）
  - content       text
  - citations     jsonb 可空（AI 消息的引用来源）
  - tokens        int 可空
  - created_at    timestamptz 索引

新增 Alembic 迁移。

新增路由 backend/app/api/chat.py（前缀 /api/chat，可选认证）：

  GET    /api/chat/sessions
         对话列表（按归属过滤，未删除，按 updated_at desc）

  POST   /api/chat/sessions
         新建对话（title 默认「新对话」，返回 session 对象）

  DELETE /api/chat/sessions/{id}
         删除对话（软删除，校验归属，级联软删除消息或保留消息）

  GET    /api/chat/sessions/{id}/messages
         获取对话消息列表（校验归属）

  改造现有 POST /api/playground/ask（不新建 chat/ask，避免 RAG 逻辑重复）
  请求体加可选字段 session_id：
  - 有 session_id：校验归属 → 保存用户消息 → SSE 流式返回 → 保存 AI 消息
    （含 citations）→ 更新 session.updated_at；首条用户消息时更新
    session.title 为消息前 20 字
  - 无 session_id：保持当前行为（不保存，纯流式），向后兼容

【决策点3：删除对话时消息怎么处理？推荐软删除 session 后消息保留可审计
 （与 kb_documents 软删除一致），检索/查询时通过 session 过滤自动排除；
 或级联硬删除消息。推荐前者】

2.5 前端设计
--------------------------------------------------------------------------------
重写 frontend/src/components/ChatView.vue（原 Playground.vue）：

状态：
- sessions：对话列表
- activeSessionId：当前对话 id（null 表示无对话）
- messages：当前对话消息
- input / streaming / error / chatBox（现有）
- sidebarCollapsed：对话列表侧栏折叠状态（可选）

方法：
- loadSessions：挂载时拉取对话列表
- newSession：点「+ 新建对话」→ POST 创建 → 加入列表 → 设为当前 → 清空消息
- selectSession：点对话项 → 设为当前 → GET 拉取历史消息
- deleteSession：点垃圾桶 → confirm → DELETE → 从列表移除 → 若删的是
  当前对话则切到空态或下一个
- send：现有发送逻辑，加 session_id 参数；若 activeSessionId 为 null 且
  用户输入了内容，自动先创建对话再发送（或提示先点新建）
  【决策点4：无对话时用户直接输入，自动新建还是提示先新建？推荐自动新建，
   体验更流畅】

布局：
- 外层 flex：对话列表侧栏（240px，可折叠到 0 或 48px）+ 聊天主区域（flex:1）
- 聊天主区域复用现有卡片样式，消息列表高度自适应
- 空态用现有 .empty 样式加气泡图标

八、风险点
================================================================================
1. playground/ask 改造加 session_id 时，SSE 流式生成过程中保存 AI 消息
   需在流结束后写入，失败不能影响已返回的内容（消息保存失败只记日志不报错）。
2. 新建对话与第一条消息的竞态：用户快速输入发送时，session 创建可能未完成，
   需前端 await 创建完成后再发消息。
3. admin 删除预置文档影响全站 RAG，已通过二次确认缓解；软删除可审计。
4. ChatView 重写时需确保不破坏现有 SSE 解析和引用来源逻辑（提交③单独验证）。
5. 新路由注册机制需施工时确认（RouterRegistry 自动扫描 or 手动登记）。
6. 对话列表侧栏与全局侧边栏并存时，窄屏（≤900px）布局需测试，避免横向滚动。
7. Alembic 迁移需在 backend/ 目录执行，且 env.py 已 import 新模型（否则生成空迁移）。
