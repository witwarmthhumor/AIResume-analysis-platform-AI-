一、全景架构：三场景 × 双轨引擎

v1 负责「问」（即时问答），v2 / 面视图负责「做」（长任务编排）；工具与能力层三者共用，故障域靠开关隔离。

▼
API：POST /api/agent/ask（SSE 流式） 事件：action / observation / delta / final / error · 另有会话 CRUD
▼
引擎：services/agent/executor.py create_openai_tools_agent + AgentExecutor，最多迭代 6 步；后台线程 + 队列做真流式
会话隔离：复用 chat_sessions 表，session_type='agent'，与在线对话（chat）互不串数据
场景二 · 一键求职准备 v2 LangGraph

二、v2「一键求职准备」图流程（LangGraph StateGraph）

planner 规划 → 能力节点执行 → verifier 校验回环 → hitl_gate 人工审批 → deliver 交付；异常统一汇总到 fail。

planner规划任务
→
load_resume读取简历
→
need_analysis路由：已有分析则跳过
→
analyzerAI 分析
→
matcher岗位匹配
→
questioner模拟出题
verifier结果校验 ⟲
→
hitl_gate人工审批 ⏸
通过
deliver交付结果
→
END完成
⟲ 回环：verifier 校验不合格 → 退回 analyzer / matcher / questioner（每节点最多重试 2 次），重试耗尽或坏输出 → fail（失败汇总终点）
⏸ 审批门禁：hitl_gate 先建审批单（TTL 30 分钟，过期自动作废）再 interrupt() 挂起图；通过 → 执行建面试场并 deliver；拒绝 / 超时 → run 终止为 failed（可 retry-node 重跑）
💾 断点续跑：PostgresSaver，thread_id = run-{run_id}；事件经总线缓冲，断线后 /stream 重连补发；恢复用 Command(resume) 从 checkpoint 继续
🔥 防护：单 run token 熔断 30000 · 限额 10 run/日 · lifespan 启动回收孤儿 run（waiting_approval 不动留审批）

💾 thread_id = interview-{session_id}，checkpoint 存独立 langgraph schema；每轮 trace 从 session.trace_json 续接
🔀 续跑 / 回退：interview_graph_enabled 且会话有 checkpoint → 走图续跑；否则自动回退旧的单轮路径（旧会话无感兼容）
